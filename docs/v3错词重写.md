# 听写本 v3：键盘听写错词重写

第三版改进原来的键盘听写流程。主界面增加「答错后再写一遍」开关，首次默认开启，之后记住当前浏览器的选择。英文朗读、中文释义朗读两种键盘听写都支持这个选项。

**线上地址：<https://hongcheng20071024-maker.github.io/tingxieben/v3/>**（已发布；根目录为原版、`v2/` 为草稿纸版，三者互不影响）

## 使用流程

1. 在主界面选择单词组和「键盘听写」，按需要开启或关闭「答错后再写一遍」。
2. 第一次拼错，或者点击「不会，查看答案」后，页面保留原答案、正确单词和英文发音按钮，并显示新的重写输入框。
3. 输入正确拼写，点击「确认重写」或按 Enter。仍然拼错会提示继续修改，拼对后才能进入下一词或查看本轮结果。
4. 本轮成绩始终按第一次作答计算。订正成功不会把第一次错误改成正确，词语仍保留在本轮错词中，可以使用「只练错词」复习。

判分继续使用原有规则：统一字符宽度、忽略大小写和首尾空格、合并连续空白、统一英文弯撇号。短语仍需完整拼写。输入框关闭拼写检查和自动大小写；输入法正在组合时按 Enter 不提交。

关闭开关后，恢复原来的答错后直接进入下一词的流程。开关只作用于键盘听写；「纸笔听写」和第二版草稿纸沿用原来的流程，不自动识别手写答案。

## 版本保存

根目录的原版与 `v2/` 文件保持不变，第三版位于独立的 `v3/`，部署后可分别访问根目录、`v2/`、`v3/`。第三版保留第二版纸笔草稿纸。草稿只存在于本轮内存，刷新、关闭或退出本轮会清除，需要保留时请先保存每页 PNG。

本选项保存在当前浏览器，未加入云端同步设置。词库继续使用原有存储和同步功能；不要通过清除网站数据来切换版本，切换设备或浏览器前建议导出词库备份。

## 构建

运行 `python tools/build_v3.py`。只使用 Python 标准库，输出必须是项目内的 `v3/`。

构建先验证 `source/听写本.html` 的原版 Git blob SHA，再对 `source/v3-patches.json` 的每个接入点要求恰好匹配一次，然后把 `source/rewrite-spelling.js` 的原生 React 组件插入同一应用作用域。任何接入点发生变化都会停止构建，防止静默误替换。`source/rewrite-spelling.css` 与第二版的草稿纸源码一起内嵌到页面。

原始作答记录不被订正组件修改；下一词按钮与推进函数均检查订正是否完成，订正组件有独立状态。退出或重新练习沿用原有会话生命周期，下一词清除订正状态。

第三版离线缓存按版本、目录和页面内容隔离，不主动刷新正在进行的听写。原版激活时可能清理其他版本缓存，正式离线听写前应联网打开新版，再在未开始练习时断网刷新确认；刷新会清空本轮草稿。

## 验证与限制

`tools/test_rewrite.cjs` 在真实 Chromium / WebKit 页面上检查开关持久化、首次错误保留、空白与错误订正拦截、正确订正、原本答对流程、查看答案、最后一词、成绩与错词复习、重新练习、退出确认、中文朗读以及纸笔草稿保留，并检查 PC、iPad 横竖屏和 iPhone 尺寸布局。

`tests/v3-worker.test.cjs` 在模拟 Service Worker 环境检查缓存隔离与离线回退。

本仓库发布时的实际验证结果：`tools/build_v3.py` 从源码重建出的 `v3/` 与开发产物**逐字节一致**（离线版本标识 `c9de84d01964604c6ea5`）；`tools/test_rewrite.cjs` 在 **Chromium 与 WebKit 各 11/11 通过、零浏览器脚本异常**；`tests/v3-worker.test.cjs` 全部通过（含「不清除 v1 / v2 缓存」断言）；线上 `v3/` 与本地产物逐字节一致，并在真实站点上断网验证过完整流程。

浏览器测试的语音和输入法事件采用模拟；没有验证真实 iPad、Apple Pencil、设备音色或线上安装后的离线流程。
